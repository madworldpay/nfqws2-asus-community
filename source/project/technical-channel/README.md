# Временный технический канал

Внизу панели — кнопка «Технический канал» и справка `?`. Владелец после
предварительной договоренности с Администратором вставляет выданную ссылку и
нажимает «Подключить». Для этого нужен защищённый вход в панель. ПК владельцу
не требуется. Канал не отправляет заявку на поддержку и не включается сам.

Администратор получает возможность выполнять команды с правами root: это
доверенный сеанс диагностики или настройки, а не изолированная среда. Владелец
видит состояние, срок и кнопку отключения. При остановке, истечении срока,
сбое процесса или перезагрузке новые команды блокируются; выполняемая команда
также прекращается. Уже сделанные Администратором изменения настроек сохраняются.

Контроллер проверяет и исходящее соединение, и внутренний SSH-сервер. Если один
из них завершился, канал закрывает оставшийся процесс и освобождает обратный
порт. Остановка и аварийное завершение контроллера используют ту же очистку.
Она относится только к процессам текущего подключения: новый сеанс и обычный
SSH роутера не затрагиваются. Повторное подключение не продлевает срок ссылки.

## Подготовка Администратором

Инструменты ниже запускаются на доверенном ПК с Python 3 и `cryptography`.
Доступ к VPS — обычный заранее настроенный root SSH с проверкой ключа хоста.
Серверу нужны OpenSSH, systemd, Python 3, useradd/userdel и pkill.

Отдельный закрытый RSA-ключ подписи хранится у Администратора. В пакете находится
только соответствующий `technical-channel-public.pem`. Закрытый ключ в Git,
пакетах, на VPS и в диагностике хранить нельзя. Путь к нему передаётся аргументом.

```sh
python3 admin.py --server VPS_IPV4 --remote-port 44901 --minutes 60 \
  --label 'Имя владельца' --signing-key /private/technical-channel-private.pem \
  --known-hosts /private/vps-known-hosts --output /private/new-session
```

Каталог результата должен быть пустым и иметь права 0700. Передайте владельцу
только **CONNECT.txt**. В нём ссылка с ограниченным временным ключом канала;
не публикуйте её. `operator` — отдельный закрытый ключ Администратора, его
нельзя передавать владельцу или копировать на VPS. `session.json` содержит
имя сеанса и срок без закрытых ключей. `--control-path` позволяет использовать
уже открытое доверенное SSH-соединение Администратора.

Ссылка проверяется на роутере без загрузки её адреса. Она содержит подписанные
адрес/порт VPS и его ключ SSH. При переезде выдайте новую ссылку: обращаться к
старому VPS и пересобирать пакет не требуется. Уже сохранённый другой ключ
того же IP автоматически не заменяется — конфликт нужно разобрать отдельно.

## Соединение и отзыв

На VPS создаётся отдельная учётная запись `nfqs-…` без shell/TTY и локальных
перенаправлений. Разрешён ровно один обратный порт, только на `127.0.0.1`.
Публичного SSH-порта роутера канал не открывает. Автоматический таймер отзывает
учётную запись по сроку. Для немедленного отзыва на VPS:

```sh
python3 /usr/local/libexec/nfqws-technical-server.py revoke SESSION_ID
```

На ПК с прямым приёмником оператор обращается к обратному порту
`127.0.0.1:remote_port` из `session.json`; VPS для этого не нужен. `connect.py`
определяет имя учётной записи UID 0 автоматически, затем использует ключ
`operator` для команды. Владельцу по-прежнему достаточно вставить подписанную
строку в WebUI и нажать «Подключить»; имя входа и пароль ему сообщать не нужно.

```sh
python3 connect.py --session-dir /private/new-session \
  --router-known-hosts /private/router-known-hosts \
  --router-host-key-alias owner-router --command '/bin/busybox id -u'
```

`owner-router` — уже проверенный ключ SSH самого роутера в указанном known_hosts.
Проверка ключа обязательна и при определении имени, и при выполнении команды.
Новый ключ сначала проверяют через существующий доверенный источник;
автоматическое принятие ключа из того же соединения не создаёт доверия.
Без `--command` инструмент выводит только session_id и найденное имя.
На прошивках с ограниченным PATH используйте абсолютные пути команд.
Если приёмник расположен на VPS, перенаправьте его loopback-порт на такой же
локальный порт ПК через свой обычный доверенный SSH, затем запустите инструмент
на ПК. Ключ оператора остаётся на ПК. Учётная запись туннеля `nfqs-…` shell/TTY не получает.
Интерактивная оболочка без команды и PTY на роутере также не предоставляются.

Временный loopback Dropbear публикует через `-b` ровно одну строку:
`NFQWS2-TECH-META/1 SESSION_ID UID0_LOGIN`. Это открытые метаданные, без пароля,
ключей и подписанной ссылки. Они передаются внутри существующего
аутентифицированного туннеля и SSH с проверенным ключом роутера. Первая короткая
SSH-попытка запрашивает только метод `none` для фиксированного служебного имени,
не предлагает ключ оператора и закрывается до следующего соединения.
Инструмент принимает единственную корректную строку с ожидаемым session_id;
при несовпадении, неизвестной версии или небезопасном имени команда не запускается.
OpenSSH должен показывать banner (`LogLevel=INFO`); `ERROR` подавляет его.
Формат подписанного приглашения, forced guard, срок и отзыв не меняются.
Файл banner имеет режим 0600 и удаляется при завершении только при совпадении
его activation_id, inode, устройства и точного содержимого.

Это требует обновлённого клиента на роутере. Уже работающие сборки 87 и 90 не
передают имя: один новый инструмент на ПК этого не исправляет. Сначала нужен
обычный авторизованный путь обновления клиента, затем новое подключение;
поиск имён и обход авторизации не выполняются.

На роутере используются штатные Dropbear и PHP/OpenSSL пакета. Дополнительный
Dropbear слушает только loopback, отключает пароль и перенаправления, а для
каждой команды принудительно вызывает проверку живого сеанса и срока. Обычный
SSH, пароль роутера, маршруты, DNS, VPN и firewall не перенастраиваются.
Временные закрытые данные находятся в `/tmp`; постоянный закрытый журнал
в каталоге настроек панели содержит только сведения для восстановления файлов
открытых ключей. Проверяются одновременно время системы, uptime и boot ID.

Реальная проверка проводится на доступном оборудовании; совпадение архитектуры
не заменяет проверку конкретной прошивки и её сборки Dropbear.
