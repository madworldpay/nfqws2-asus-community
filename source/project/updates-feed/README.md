# Закрытый канал пакетов

Это отдельный канал доставки IPK для приватного этапа проекта. Он не отправляет
диагностику и не требует от маршрутизатора доступа к учётной записи GitHub.
Подпись выпуска проверяется на маршрутизаторе закреплённым открытым ключом.

## Развёртывание оператором

Скрипты `common.py`, `server.py` и `publish.py` устанавливаются в
`/usr/local/lib/nfqws-updates`, root:root, каталог0755, файлы0644. Отдельный
системный пользователь и группа `nfqws-updates` не имеют shell и домашнего
каталога. Хранилище `/srv/nfqws-updates` принадлежит root:nfqws-updates;
каталоги0750, готовые файлы0640. Только оператор root публикует выпуски.

В `/etc/nfqws-updates/feed-config.json` (root0600) оператор размещает JSON
с полями `token` (случайный base64url, не менее43 символов) и `release_root`
(`/srv/nfqws-updates`). Передавать секреты через аргументы команд нельзя.
Systemd `LoadCredential` предоставляет конфигурацию отдельному процессу.
Закрытый ключ RSA3072 хранится отдельно, root0600, и серверу не доступен.

Установите unit `nfqws-updates.service`. Он слушает только127.0.0.1:8876;
добавьте `nginx-location.conf` в существующий HTTPS virtual host. Проверьте
`nginx -t` перед reload. Другие маршруты, почтовый relay и VPN не заменяются.
Не включайте общий access log для этого location. Сервис не пишет IP,
Authorization, query или тела ошибок в журналы.

Маршрутизатор получает отдельный root0600
`/opt/etc/nfqws-asus-web/update-channel.json`:
`origin` — HTTPS origin без пути, `token` — токен канала. Он не входит в IPK,
предпросмотр диагностики или публичный API. Токен разрешает только чтение;
публикация через HTTP отсутствует.

## Выпуск

Подготовьте в закрытом каталоге `release.json` по
`updates/package-manifest.schema.json` и оба IPK с точными размером/SHA256.
Исходные файлы должны принадлежать root и не допускать записи группы/других.
Запускайте операторский `publish.py` с путями к входному каталогу, закрытому
ключу и хранилищу (синтаксис `python3 publish.py --help`). Пароль и содержимое
ключа аргументами не передаются. Publisher проверяет IPK control, подписывает
точные байты manifest, затем атомарно переключает `current.json`.

Готовый номер версии неизменяем. Сохраняются текущий и предыдущий выпуски;
общий предел100MiB включает staging. Перед копированием проверяются квота
и минимум10MiB свободного места. Чужие файлы не удаляются. Если места мало,
новый выпуск отклоняется, действующий остаётся доступен. После публикации
проверьте отказ без токена, manifest/signature с правильным токеном и SHA256
скачанного пакета. Не выводите токен в терминал или журнал команд.

Смена ключа требует отдельного доверенного обновления IPK. Новый ключ из
самого канала автоматически не принимается. Потеря доступа к каналу не
останавливает NFQWS2 и не означает, что установлена последняя версия.
