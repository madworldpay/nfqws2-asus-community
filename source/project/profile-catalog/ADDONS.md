# Публичные дополнения импорта

`addons.py` подготавливает независимый подписанный каталог дополнений для Build92 и новее. Закрытый каталог профилей v1, его схему и `publish.py` он не изменяет. Дополнения выключены по умолчанию; после выбора применяются через общий предпросмотр импорта вместе с выбранной базовой стратегией.

Адрес каталога: `https://mad13mansprofy13.asuscomm.com:5443/nfqws-profiles/v1/addons/catalog.json`. Документы находятся в `addons/files/<sha256>.json` относительно прежнего корня v1. Резервный фиксированный источник — `https://raw.githubusercontent.com/madworldpay/nfqws2-asus-community/main/source/catalog-addons/v1/`. Он используется при транспортной недоступности основного адреса; подпись и контрольные суммы проверяются по тем же правилам. Недействительная подпись или неверное содержимое не скрываются запасным источником. Используется прежний доверенный открытый ключ каталога RSA3072 и подпись RSA PKCS#1 v1.5 / SHA256 над точными декодированными байтами `manifest`. Оболочка содержит только строки Base64 `manifest` и `signature`.

Документ содержит только `type: "nfqws2_import_addon"`, `schema_version: 1`, `id`, `title`, `description`, `kind: "scope_domains_v1"` и `domains`. Допускаются от 1 до 64 уникальных публичных DNS-имён в нижнем регистре ASCII. URL, пути, IP, маски, команды и локальные/служебные суффиксы отвергаются. Список не может задавать алгоритмы, Lua, DNS или запуск службы. Новые виды правил требуют отдельного обновления клиента.

Метаданные одобрения содержат `schema_version: 1`, возрастающую `revision` и массив `addons` (до 64 записей). Запись включает `id`, `title`, `description`, `attribution`, `updated_at`, `revision`, `min_build` (от 92), `file` и `source_sha256` — хеш точных вручную проверенных байтов. `id`, `title` и `description` должны совпадать с документом. Публикатор заменяет два последних поля на вычисленные `size` и `sha256`; дополнительных полей в подписанном манифесте нет. Максимум документа и декодированного манифеста — 65536 байт, оболочки — 131072 байта. Даты задаются в UTC как `YYYY-MM-DDTHH:MM:SSZ` и проверяются как реальные календарные даты.

Нужны Python 3 и OpenSSL. Ключ передаётся только обязательным параметром `--key`, без поиска по окружению или учётным данным. Используйте прежний ключ доверия каталога, находящийся вне репозитория и каталога веб-сервера, с правами 0600 или 0400. Публикатор не обращается к сети и не устанавливает обновления.

Из каталога `source/project`:

```sh
python3 profile-catalog/addons.py \
  --metadata profile-catalog/examples/approved-addons.example.json \
  --addons-dir profile-catalog/examples \
  --key /private/profile-catalog-private.pem \
  --output /private/staged/v1/addons
```

Пример содержит только публичные данные. Перед реальной публикацией проверьте содержимое, дату и ревизии; при изменении документа пересчитайте `source_sha256`. Каталог назначения должен называться `addons`, чтобы случайно не заменить прежний `v1/catalog.json`. Ни одобренные входные файлы, ни ключ не могут находиться внутри каталога назначения. Символические ссылки и входные файлы с жёсткими ссылками отвергаются.

На выходе только `catalog.json` и `files/<sha256>.json`. Повторная подготовка тех же входов тем же ключом в новом каталоге даёт те же байты и подпись. В существующем каталоге ревизия должна строго возрастать; прежняя оболочка проверяется тем же ключом. Файлы с хешем неизменяемы, предыдущие версии сохраняются. Запускайте одного публикатора за раз. При выкладке сначала добавьте новые неизменяемые файлы, затем атомарно замените только `addons/catalog.json`. Для нового пути отдельно настройте разрешённое чтение на существующем HTTPS-сервере и проверьте подпись, хеши и доступность прежнего каталога профилей.

`addons-nginx.conf.example` — отдельный пример для существующего HTTPS Nginx, использующий прежние зоны ограничений из `nginx-http.conf.example` и обработчик `@nfqws_profile_limited`. Он разрешает только чтение точного каталога и файлов с хешем, выключает просмотр каталогов и не меняет правила прежних путей v1. Фактический сервер и каталог файлов проверяет оператор; пример сам не меняет текущее размещение сервиса. Если требуется этот прокси, подключите пример в существующий `server {}` перед другими регулярными `location`, проверьте `nginx -t`, затем проверьте новые и прежние адреса.

## Область публичного примера Riot

`examples/riot-web.json` — собственный небольшой перечень доменов, а не заимствованная игровая стратегия. Названия Riot Games, League of Legends и VALORANT принадлежат Riot Games; авторство сервисов сохранено в `attribution` метаданных. Правила и тексты сторонних стратегий не копируются.

Проверка источников 2026-11-06:

- [Официальный сайт Riot Games](https://www.riotgames.com/en) связывает сервисы с [leagueoflegends.com](https://www.leagueoflegends.com/en-us/) и [playvalorant.com](https://playvalorant.com/en-us/).
- [Публичный статус Riot Client](https://riot-client.secure.dyn.riotcdn.net/channels/public/x/status/keystonefoundationlive.json) подтверждает использование `riotcdn.net` веб-службой Riot.

В начальный пример включены только `riotgames.com`, `riotcdn.net`, `leagueoflegends.com` и `playvalorant.com`. Перечень ограничен веб-службами и не является полным списком игровых узлов Riot.

Дополнение использует выбранную базовую стратегию только для указанной доменной области. Оно не означает рабочий игровой UDP, доступ ко всем адресам AS6507, изменение DNS или подтверждённую доступность у конкретного провайдера. Неограниченная базовая стратегия уже охватывает эти домены; существующие исключения сохраняют приоритет.

Проверки используют только временный тестовый RSA3072-ключ:

```sh
python3 -m unittest discover -s profile-catalog -p 'test_addons.py' -v
```
