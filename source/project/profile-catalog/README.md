# Каталог пресетов: обслуживание

Панель загружает подписанный каталог и выбранный JSON из нашего облака. Выбор блоков, предпросмотр и применение выполняет обычный импорт. Отправленные пользователями сведения не публикуются автоматически.

## Подготовка

Нужны Python 3, OpenSSL и PHP CLI с OpenSSL. Закрытый ключ, одобренные JSON и метаданные храните вне репозитория и каталога веб-сервера. В IPK находится только `asus/profile-catalog-public.pem`; ключ независим от подписи обновлений пакета.

Метаданные содержат `schema_version: 1`, возрастающую `revision` и массив `profiles`. Для каждой записи нужны поля схемы `support/profile-catalog.schema.json`, кроме вычисляемых `size` и `sha256`. Вместо них укажите `file` — имя проверенного JSON — и `source_sha256` — SHA256 именно одобренных байтов. Категории: `provider` и `global`. `min_build` задаёт минимальный Build панели.

```sh
python3 profile-catalog/publish.py \
  --metadata /private/approved.json \
  --profiles-dir /private/profiles \
  --private-key /private/profile-catalog-private.pem \
  --output /private/staged/v1 \
  --php /path/to/php
```

Публикатор проверяет формат, хеши вложений и импорт. Диагностика, сведения о клиентах, ключи и Lua-вложения в каталог не допускаются. Проверка не доказывает скорость или доступность сервисов у каждого провайдера. Запускайте одного публикатора за раз.

На выходе только `catalog.json` и `files/<sha256>.json`. Сначала загрузите новые неизменяемые файлы, затем атомарно замените каталог. Старые файлы сохраняйте для уже открытых окон импорта. Не понижайте ревизию; откат содержимого оформляйте новой ревизией.

## Веб-сервер

`nginx-http.conf.example` включается в `http {}`. `nginx.conf.example` — в существующий HTTPS `server {}`, до других регулярных `location`. Корень файлов: `/srv/nfqws-profiles/v1`. Закрытый ключ туда не копируется.

Перед изменением сохраните затронутую конфигурацию. После загрузки файлов выполните `nginx -t`, затем перезагрузку конфигурации только Nginx. Проверьте HTTPS, подпись каталога, хеши JSON и прежние служебные адреса. Правила разрешают только чтение двух видов объектов, ограничивают частоту запросов и не открывают просмотр каталогов.

## Обновление глобальных стратегий

Исходный адрес и проверенная ревизия указаны в [upstreams.json](upstreams.json). Источник — репозиторий автора меню, а не установленный роутер.

1. Получите свежую ревизию через официальный GitHub API, закрепите commit и проверьте Git blob ID файлов.
2. Разберите конфиги как данные. Сохраните имена и авторство; перенесите только параметры и необходимые списки/blobs. Lua поставляется нашим пакетом.
3. Проверьте пути, содержимое blobs, порты, аргументы движка и запуск Lua на обеих архитектурах. Затем проверьте выбор блоков и предпросмотр нашим импортом без изменения локальных настроек роутера.
4. Работу трафика проверяйте отдельно. Проблемный вариант не включайте в одобренный каталог. Обновите закреплённую ревизию и подпишите вручную одобренные JSON новой ревизией каталога.

Рабочие профили не заменяются автоматически при изменении upstream.
