# SmartDNS

Мастер SmartDNS доступен на ASUS/Entware и OpenWrt. Описание hook `dnsmasq.postconf` и путей `/opt` ниже относится к ASUS/Entware; нативный OpenWrt использует свою интеграцию с dnsmasq.

## Зачем он нужен

**SmartDNS — отдельная утилита, а не встроенная функция ASUS.**
Правила «сайт → выбранный DoT/DoH» и фиксированные ответы в нашей схеме
выполняет SmartDNS. Панель NFQWS2 устанавливает и настраивает его.
Так на ASUS воспроизводится привычная пользователям Keenetic схема DNS для сайтов.

DNS возвращает IP сайта. Разные DNS могут выбирать разные адреса CDN,
на которых одна стратегия работает по-разному. SmartDNS позволяет:

- назначить отдельный DoT/DoH нужным сайтам;
- выбрать DNS для остальных сайтов;
- закрепить IP домена, если это нужно проверенному профилю.

Для этих возможностей установите SmartDNS через нашу панель. Он помогает
получать нужные адреса сайтов, а NFQWS2 обрабатывает соединения с ними.
Если результат стратегии зависит от DNS, переносите их вместе: одна стратегия
с другими адресами может дать другой результат. Фиксированный IP может устареть.

## Сколько можно добавить

В одном профиле нашей панели:

- до **32 DNS-серверов** суммарно: DoT, DoH, обычный UDP или TCP;
- до **256 привязок «домен → DNS»** на все серверы; один домен у двух DNS занимает две привязки;
- до **64 фиксированных ответов**, до **8 IP** в каждом.

Можно включать поддомены. Общий размер профиля — до **64 КиБ**, поэтому
все пределы не обязательно достижимы одновременно. Это ограничения текущей
панели, а не пределы самой утилиты SmartDNS.

## Настроить через панель

1. Откройте вкладку **SmartDNS**. Чекап покажет условия установки.
2. Нажмите **«Установить SmartDNS»**, если движок ещё не установлен.
3. Выберите DoT/DoH из списка или задайте свой. Укажите сайты для отдельного DNS.
   **«По умолчанию»** означает DNS для сайтов без отдельного назначения.
4. При необходимости добавьте **фиксированный ответ** — домен и конкретный IP.
5. Нажмите **«Проверить профиль»**. Просмотрите DNS по умолчанию, назначения доменов и полный конфиг, затем нажмите **«Подключить»**.
6. Проверьте DNS с устройства и нажмите **«DNS работает — оставить настройки»**.

Нужен хотя бы один DNS **«По умолчанию»**. Для своего сервера с именем укажите IP подключения в bootstrap; для DoT/DoH — имя сертификата, для DoH также полный HTTPS URL. Bootstrap содержит адреса DNS-сервера, а не сайта; проверка сертификата сохраняется.

Фиксированный ответ имеет приоритет над выбором DNS для пересекающегося домена; предпросмотр показывает такие пересечения. Для фиксированного IP можно записать дату последней проверки.

Редактор сначала загружает сохранённый черновик. После импорта он подхватывает новый профиль, пока нет несохранённых ручных правок; при таких правках сохраните или отмените их перед переходом к импортированным данным. Проверка и предпросмотр используют сохранённый сервером профиль с его нормализацией, а не прежнее содержимое формы.

Установка движка и проверка профиля сами по себе DNS не переключают. Чекап читает состояние роутера и не проверяет открытие сайтов. Если SmartDNS уже управляется вне мастера, черновик можно проверить, но подключение блокируется до переноса управления.

**«Проверить профиль»** проверяет настройки и запуск конфигурации; состав серверов
от этого не меняется. При подключении проверяется общий ответ DNS. Затем у вас
есть **120 секунд**, чтобы проверить сайты с устройства и подтвердить результат.
Без подтверждения защитный механизм возвращает прежний DNS. Защита работает на роутере и после закрытия окна; при повторном открытии панель показывает текущее состояние.

Можно использовать готовые параметры DoT/DoH или свой сервер. Если отдельный
сайт не открывается, проверьте ответ назначенного ему DNS и сам сервис:
успешное подключение мастера не заменяет проверку каждого домена.

## Как подключается к Merlin

Штатный **dnsmasq остаётся работать**: DHCP и локальные имена сохраняются.
Внешние запросы передаются локальному SmartDNS на отдельном порту.
Панель использует `dnsmasq.postconf`, чтобы правило сохранялось после перезапуска DNS.
Это служебный скрипт Merlin, а не модуль ядра и не подготовка ARK.

В Merlin для этого используется поддержка пользовательских JFFS-скриптов.
Существующие чужие команды сохраняются. Подключение SmartDNS и подготовка ARK —
разные действия: ARK проверяется для обработки трафика NFQWS2.
Гостевые сети, SDN и VPN могут использовать отдельный путь DNS.

При подключении учитываются обычные файлы DNS-настроек VPN: правила `ipset`,
локальные имена и параметры клиентов сохраняются. Исходные файлы VPN не меняются.
Если способ подключения несовместим, панель показывает причину до переключения.
Статус **«SmartDNS подключён»** проверяет и процесс, и перенаправление запросов dnsmasq.

## Возврат и обновление

Нажмите **«Вернуть прежний DNS»**. Сначала восстанавливается прежний путь dnsmasq,
затем останавливается наш процесс SmartDNS. Черновик остаётся для дальнейшей настройки.
Не останавливайте единственный DNS-сервер раньше возврата перенаправления.

Для замены подключённого профиля сначала нажмите **«Вернуть прежний DNS»**, затем измените сохранённый черновик, проверьте и подключите его снова. **«Загрузить последний подтверждённый профиль»** помогает вернуться к прежнему рабочему варианту.

На ASUS администратор может проверить состояние по SSH командой `/opt/bin/nfqws2-smartdns-control status`, а вернуть DNS — `/opt/bin/nfqws2-smartdns-control rollback`.

После обновления пакет пытается восстановить ранее подтверждённый профиль,
даже если в редакторе уже другой черновик. Черновик сохраняется.
Явный возврат к прежнему DNS отменяет автоматическое восстановление.
Если подключение не удалось или другой сервис изменил путь DNS, панель показывает подсказку.

Встроенный DoH браузера, Private DNS телефона или DNS внутри VPN может обходить
DNS роутера. Проверяйте фактический путь запроса, когда результаты различаются.

DNS-тест оригинального DPI Detector независимо обращается к собственному списку публичных UDP/DoT/DoH-серверов. Его процент не проверяет всю цепочку SmartDNS или DNS на клиенте. «Проверка сервисов» использует системное разрешение имён роутера для своих URL. [Как различать эти проверки](DPI-DETECTOR.md).

Если DNS — часть удачного профиля, отметьте его вместе со стратегией в
**«Экспорт / поделиться»**, проверьте предпросмотр и отправьте результат проекту.
Это помогает воспроизвести результат в другой сети.
