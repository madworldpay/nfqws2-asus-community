# SmartDNS

## Зачем он нужен

**SmartDNS — отдельная утилита, а не встроенная функция ASUS.**
Правила «сайт → выбранный DoT/DoH» и фиксированные ответы в нашей схеме
выполняет SmartDNS. Панель NFQWS2 устанавливает и настраивает его.
Так на ASUS воспроизводится привычная пользователям Keenetic схема DNS для сайтов.

DNS возвращает IP сайта. Разные DNS могут выбирать разные адреса CDN,
на которых одна стратегия работает по-разному. SmartDNS позволяет:

- назначить отдельный DoT/DoH нужным сайтам;
- выбрать DNS для остальных сайтов;
- закрепить IP домена, если это нужно проверенному профилю.

Для этих возможностей установите SmartDNS через нашу панель. Он помогает
получать нужные адреса сайтов, а NFQWS2 обрабатывает соединения с ними.
Если результат стратегии зависит от DNS, переносите их вместе: одна стратегия
с другими адресами может дать другой результат. Фиксированный IP может устареть.

## Сколько можно добавить

В одном профиле нашей панели:

- до **32 DNS-серверов** суммарно: DoT, DoH, обычный UDP или TCP;
- до **256 привязок «домен → DNS»** на все серверы; один домен у двух DNS занимает две привязки;
- до **64 фиксированных ответов**, до **8 IP** в каждом.

Можно включать поддомены. Общий размер профиля — до **64 КиБ**, поэтому
все пределы не обязательно достижимы одновременно. Это ограничения текущей
панели, а не пределы самой утилиты SmartDNS.

## Настроить через панель

1. Откройте вкладку **SmartDNS**. Чекап покажет условия установки.
2. Нажмите **«Установить SmartDNS»**, если движок ещё не установлен.
3. Выберите DoT/DoH из списка или задайте свой. Укажите сайты для отдельного DNS.
   **«По умолчанию»** означает DNS для сайтов без отдельного назначения.
4. При необходимости добавьте **фиксированный ответ** — домен и конкретный IP.
5. Нажмите **«Проверить профиль»**, затем **«Подключить»**.
6. Проверьте DNS с устройства и нажмите **«DNS работает — оставить настройки»**.

Проверка профиля проверяет конфигурацию. Она не подтверждает доступность каждого
внешнего DNS и не исключает выбранные серверы из профиля.
При подключении проверяется общий ответ DNS. Если пробное подключение
не подтверждено, защитный механизм возвращает прежний DNS.

Недоступный сервер можно сохранить и назначить сайтам. Доступ к нему и подходящий
протокол выбирает пользователь. При смешении серверов ответы могут различаться.
Одно наличие обычного DNS не означает, что «всё сломается»: важно, какие запросы
ему передаются и не обходят ли клиенты ваши правила.

## Как подключается к Merlin

Штатный **dnsmasq остаётся работать**: DHCP и локальные имена сохраняются.
Внешние запросы передаются локальному SmartDNS на отдельном порту.
Панель использует `dnsmasq.postconf`, чтобы правило сохранялось после перезапуска DNS.
Это служебный скрипт Merlin, а не модуль ядра и не подготовка ARK.

Для правил «сайт → DNS» отдельный hook сам по себе не нужен. Он требуется
выбранному способу подключения к прошивке. В Merlin должна работать поддержка
пользовательских JFFS-скриптов; существующие чужие команды сохраняются.
Другие прошивки, гостевые сети, SDN и VPN могут иметь отдельный путь DNS.

При подключении учитываются обычные файлы DNS-настроек VPN: правила `ipset`,
локальные имена и параметры клиентов сохраняются. Исходные файлы VPN не меняются.
Если способ подключения несовместим, панель показывает причину до переключения.
Статус **«SmartDNS подключён»** проверяет и процесс, и перенаправление запросов dnsmasq.

## Возврат и обновление

Нажмите **«Вернуть прежний DNS»**. Сначала восстанавливается прежний путь dnsmasq,
затем останавливается наш процесс SmartDNS. Черновик остаётся для дальнейшей настройки.
Не останавливайте единственный DNS-сервер раньше возврата перенаправления.

После обновления пакет пытается восстановить ранее подтверждённый профиль,
даже если в редакторе уже другой черновик. Черновик сохраняется.
Явный возврат к прежнему DNS отменяет автоматическое восстановление.
Если подключение не удалось или другой сервис изменил путь DNS, панель показывает подсказку.
Сведения о проверках и ограничениях — в [совместимости](COMPATIBILITY.md).

Встроенный DoH браузера, Private DNS телефона или DNS внутри VPN может обходить
DNS роутера. Проверяйте фактический путь запроса, когда результаты различаются.
