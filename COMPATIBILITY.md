# Поддержка без гадания по названию модели

Аппаратная база проекта — **GT-BE19000AI, Asuswrt-Merlin 3006.102.9_0, Linux 4.19.294**. На этой системе проверены установка, панель, службы, доставка в NFQUEUE и отдельные контрольные IPv4 HTTPS-сценарии в режиме загрузки без ARK.

Это относится к конкретным проведённым опытам. Каждый новый пакет, стратегия или режим маршрутизации требует своей проверки.

Build 6 установлен на испытанном ASUS без перезагрузки; проверены панель,
службы и сохранность настроек. Контрольное сравнение самостоятельного обхода
в этом обновлении не повторялось.

| Семейство | Что известно |
| --- | --- |
| GT-BE19000AI с указанной Merlin | Есть аппаратные испытания; для NFQUEUE важен режим ARK |
| GT-BE19000 | Целевая модель; отдельной аппаратной приёмки нет |
| Другие AArch64 ASUS | Анализируются; совпадения CPU недостаточно |
| ARMv7 / Entware 2.6 и 3.2 | Упаковка и частные runtime проверены локально; аппаратная NFQUEUE на старом ядре не подтверждена |
| MIPS | Не поддерживается |

IPv6, QUIC, скорость и длительная работа на всех моделях не прошли полную аппаратную приёмку. QEMU использует ядро хоста и не подтверждает работу NFQUEUE старой прошивки.

Нужны возможности ядра для NFQUEUE, conntrack, connbytes, multiport и mark, а также реальное прохождение клиентского трафика через выбранный WAN ASUS. Аппаратное ускорение, ARK и другие пути обработки могут влиять на доставку пакетов.

Установщик не прошивает устройство и не добавляет отсутствующие модули ядра. Анализ образа прошивки служит основанием для следующего теста, а не значком «совместимо».
