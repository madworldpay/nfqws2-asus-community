# Поддержка без гадания по названию модели

По архитектуре проект рассчитан на широкий круг современных ASUS с Entware:
подготовлены пакеты для ARMv7 и AArch64. Это даёт хороший потенциал расширения
поддержки, но у отдельных моделей и прошивок возможны исключения — нужны
подходящие возможности ядра и доставка клиентских пакетов в NFQUEUE.

Ниже отдельно указано, что уже проверено на устройстве и что ещё требует
испытаний. Наличие подходящего IPK само по себе не означает, что аппаратная
проверка этой модели завершена.

| Семейство | Что известно |
| --- | --- |
| GT-BE19000AI | Проверенный пример ASUS с ARK; штатное отключение ARK испытано |
| GT-BE19000 | Целевая модель; отдельной аппаратной приёмки нет |
| Другие AArch64 ASUS | Анализируются; совпадения CPU недостаточно |
| RT-AC87U / Merlin 384.13_10 | В испытательном пакете после Build 20 подтверждены очередь и самостоятельный выбранный LAN IPv4 TCP; требуется точный дополнительный профиль |
| Другие ARMv7 / Entware 2.6 и 3.2 | Частные runtime проверены; результаты 87U не переносятся на другие ядра автоматически |
| MIPS | Не поддерживается |

Один из примеров — **GT-BE19000AI с ARK**. ARK удалось штатно отключить;
после этого NFQWS2 работает без нареканий по текущему опыту использования.
На этой модели также проверены установка, панель, приём пакетов NFQUEUE
и работа выбранной обработки на контрольных IPv4 HTTPS-соединениях.

IPv6, QUIC, скорость и длительная работа на всех моделях не прошли полную аппаратную приёмку. QEMU использует ядро хоста и не подтверждает работу NFQUEUE старой прошивки.

Нужны возможности ядра для NFQUEUE, conntrack, connbytes, multiport и mark, а также реальное прохождение клиентского трафика через выбранный WAN ASUS. Аппаратное ускорение, ARK и другие пути обработки могут влиять на доставку пакетов.

Выпущенный Build 20 не добавляет отсутствующие модули ядра. В следующей испытательной ветке предусмотрен модуль только для точного 87U / 384.13_10, с проверкой штатных файлов и без перепрошивки. [Подробности двух пакетов](BUILD-IMPACT.md). Анализ образа прошивки служит основанием для следующего теста, а не значком «совместимо».

## Что будет без поддержки NFQUEUE

Служба проверяет необходимые возможности ядра до запуска движка и подключения правил к трафику. При отсутствии NFQUEUE или нужных расширений она откажется запускаться с сообщением об ошибке; неподдерживаемый режим не включается принудительно. Файлы пакета и панель могут остаться установленными — их можно [удалить обычной командой](INSTALL.md#как-остановить-и-удалить).

Установка не меняет настройки ARK автоматически. Принятые ядром правила и нулевые счётчики — отдельный случай: возможен конфликт с ARK или другим путём обработки, поэтому одного успешного запуска недостаточно. [Подробнее о проверке перед запуском](INSTALL.md#если-ядро-не-поддерживает-nfqueue).

## Как сообщество поможет расширить поддержку

Потенциал проекта шире нынешней таблицы. Добровольные диагностические отчёты
и результаты проверок владельцев других ASUS помогут находить общие
закономерности между прошивками, замечать ограничения и дополнять таблицу
проверенными фактами. Будущий обмен стратегиями позволит учитывать ещё и
сервис, оператора и регион — рабочий пример будет полезнее безымянного набора
параметров.

Так каждый участник сможет помочь следующему: отчётом о проблеме, удачным
тестом или позднее своей стратегией. Текущие ограничения остаются в таблице
до проверки; [дальнейшие планы](ROADMAP.md) показывают, куда хотим двигаться.

Для начала достаточно [инструкции установки](INSTALL.md) и короткой [памятки](USAGE.md). Пакеты бесплатные; участие в проверках и поддержка разработки добровольные.

## SmartDNS и ресурсы

На 87U с 256 МиБ RAM испытаны USB Entware и SmartDNS 48.4. Это объём испытанного устройства, не минимальная RAM для любых стратегий. Один DoT был достаточен в строгом сравнении; выбор адреса CDN влиял на Instagram и постеры. [Условия, замеры, DNS и откат](SMARTDNS.md). Официальный DPI ARMv7 на этом аппарате требует отдельной совместимой сборки и не считается проверенным обычным установщиком.
