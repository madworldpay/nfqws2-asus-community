# OpenWrt: установка и совместимость

Нативный пакет `nfqws2-native` использует службы OpenWrt `procd`, сетевые интерфейсы
`netifd` и правила `firewall4` / `nftables`. Entware для него не требуется.
Внутри — наша общая панель: стратегии, выбор устройств, импорт своего JSON или
пресета из облака, предпросмотр и отмена импорта, SmartDNS, диагностика и обновления.

## Установить

Войдите по SSH **в роутер с OpenWrt** от `root` и выполните:

```sh
( nfqws_url=https://raw.githubusercontent.com/madworldpay/nfqws2-asus-community/main/install.sh; nfqws_file=$(mktemp) && trap 'rm -f "$nfqws_file"' 0 && { curl -fL --connect-timeout 10 --max-time 60 "$nfqws_url" -o "$nfqws_file" || uclient-fetch -T 20 -O "$nfqws_file" "$nfqws_url"; } && sh "$nfqws_file" )
```

Команда определяет версию OpenWrt и её точную архитектуру, выбирает IPK для
OpenWrt 24.10 или APK для OpenWrt 25.12, проверяет подпись выпуска и SHA256.
Недостающие компоненты устанавливаются из настроенных подписанных репозиториев
OpenWrt. Если для этого требуется заменить уже установленные системные пакеты,
установщик объяснит причину; сначала обновите их штатным способом OpenWrt.

При первой установке обработка выключена. После обновления сохраняются настройки
и прежнее состояние служб. Закрытие SSH после начала фоновой установки не отменяет
её. Если произошла ошибка, сохраните названный установщиком каталог журналов.

Проверка скачанного установщика без установки пакета: `sh install.sh --check`.
Если PHP для проверки ещё нет, этот режим перечислит нужные компоненты и остановится.

### Установить пакет вручную

Посмотрите `DISTRIB_RELEASE` и `DISTRIB_ARCH` командой:

```sh
cat /etc/openwrt_release
```

Выберите файл **для этой архитектуры и серии OpenWrt**. Загрузите его в `/tmp`
роутера. Для 24.10 используйте `opkg install /tmp/имя-пакета.ipk`; для 25.12 —
установщик выше: он подготавливает проверку подписи нашего APK отдельно от
системного хранилища ключей. Пакеты ASUS/Entware и нативные пакеты OpenWrt имеют
разные имена и архитектуры; выбирайте нужный вариант по этой таблице.

## Настроить панель

1. Откройте адрес, выданный установщиком: `http://IP-роутера:90`. По умолчанию используется учётная запись `root` OpenWrt. Пароль панели можно задать отдельно через «Сменить пароль».
2. Оставьте автоматический выбор WAN или выберите логический интерфейс OpenWrt, например `wan` или `wan6`. Для PPPoE фактическое устройство определяется через `netifd`.
3. Выберите устройства и стратегию. В режиме «Только выбранные» один адрес — это одно устройство: например `192.168.1.20` и `192.168.1.30`, каждый с новой строки. Подсеть `192.168.1.0/24` выбирает сразу всю эту сеть. Закрепите адреса отдельных устройств в **LuCI → Сеть → DHCP и DNS → Статические аренды**.
4. Можно импортировать свой JSON или пресет из облака. Изначально выбрано всё, что включил автор профиля; лишнее можно снять. Проверьте предпросмотр и примените. Пути поддерживаемых файлов адаптируются к OpenWrt; WAN и выбор локальных устройств сохраняются от вашего роутера, а не заменяются чужими адресами.
5. Для правил «сайт → DNS» откройте SmartDNS, подготовьте профиль, выполните пробное подключение и подтвердите результат. Штатная конфигурация `dnsmasq` сохраняется; без подтверждения возвращается прежний DNS.
6. Запустите NFQWS2. Проверьте рост счётчиков пакетов, затем нужные сайты, видео и голос с выбранного устройства.

Панель слушает выбранную локальную сеть; LuCI и её настройки не заменяются.
Настройки NFQWS2 находятся в `/etc/nfqws2/`, панели — в `/etc/nfqws2-web/`
и `/etc/config/nfqws2-web`. Аппаратное ускорение и software flow offloading могут
обходить NFQUEUE: панель проверяет это и объясняет необходимые действия.

Экспорт и обмен стратегиями работают так же:
сначала выберите состав и предпросмотр, затем скачайте JSON или отправьте отчёт.
Рабочая стратегия для вашего провайдера полезна другим пользователям — делитесь
результатами, указав модель, прошивку и условия проверки.

## Какие устройства и пакеты

Определяющие значения — **серия OpenWrt и `DISTRIB_ARCH`**, а не бренд и не одно
название процессора. Ревизии одной модели иногда относятся к разным семействам.
Таблица приводит примеры из официального каталога OpenWrt; наличие прошивки,
работа Wi-Fi и портов зависят от поддержки самой модели в OpenWrt.

| `DISTRIB_ARCH` | Семейство / примеры | Результат проверки нашей программы |
| --- | --- | --- |
| `arm_cortex-a9` | Broadcom ARMv7: ASUS RT-AC87U, RT-AC68U, RT-AC88U | **RT-AC87U с OpenWrt 24.10 проверен на устройстве**. Другие модели: **Совместимость теоретическая** |
| `arm_cortex-a7_neon-vfpv4` | Qualcomm IPQ40xx: ASUS RT-AC58U, RT-ACRH17, Lyra | **Совместимость теоретическая** |
| `arm_cortex-a15_neon-vfpv4` | Qualcomm IPQ806x: ASUS OnHub SRT-AC1900 | **Совместимость теоретическая** |
| `aarch64_cortex-a53` | ARM64: ASUS RT-AX59U, TUF-AX4200, TUF-AX6000; устройства с такой же архитектурой OpenWrt | **Совместимость теоретическая** |
| `mips_24kc` | MIPS, big-endian: ASUS RT-AC59U, ZenWiFi CD6 | **Совместимость теоретическая** |
| `mipsel_24kc` | MIPS, little-endian: ASUS RT-AC65P, RT-AX53U; MediaTek/Ralink | **Совместимость теоретическая** |
| `mipsel_74kc` | MIPSel: ASUS RT-N16, RT-N66U, RT-AC53U | **Совместимость теоретическая** |
| `mips64_octeonplus` | Cavium/Marvell Octeon | **Совместимость теоретическая** |
| `i386_pentium4` | 32-битные x86-устройства с этой архитектурой пакетов | **Совместимость теоретическая** |
| `x86_64` | 64-битные ПК, мини-ПК и виртуальные машины с OpenWrt | **Совместимость теоретическая** |

Для каждой строки выпускаются отдельные IPK (24.10) и APK (25.12).
Оболочка панели общая; движки выбираются по ABI, разрядности, порядку байтов
и набору инструкций. Проверки сборки и изолированной среды не заменяют проверку
на конкретном роутере. Совместимость дополнительных утилит определяется отдельно:
если DPI Detector для архитектуры отсутствует, это не означает отсутствие поддержки NFQWS2.

Для установки нужны доступные репозитории именно вашей версии OpenWrt,
`firewall4`, поддержка NFQUEUE в ядре и свободное место для приложения,
зависимостей и временной установки. Установщик проверяет место по реальному
размеру выбранного пакета; USB или расширение overlay не увеличивают ОЗУ.

Официальные сведения: [каталог устройств OpenWrt](https://openwrt.org/toh/start),
[профили прошивок](https://downloads.openwrt.org/releases/25.12.6/targets/).

## Команды и удаление

```sh
/etc/init.d/nfqws2-native start
/etc/init.d/nfqws2-native stop
/etc/init.d/nfqws2-native status
/etc/init.d/nfqws2-native-web restart
```

Удаление через `opkg remove nfqws2-native` (24.10) или `apk del nfqws2-native`
(25.12) останавливает наши службы и убирает их правила. Пользовательские настройки
сохраняются. Это удаление программы; прошивка OpenWrt остаётся на устройстве.
Исходники нативной интеграции: [source/project/openwrt](source/project/openwrt/).
