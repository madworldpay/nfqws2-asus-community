# IP Health Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Remember independently confirmed unavailable IP endpoints and reduce repeat waiting while preserving working NFQWS strategies.

**Architecture:** A separate pinned-engine Lua observer exchanges bounded RAM observations with a marked PHP prober/controller. Persistent incident state feeds a short-lived enforcement manifest; authenticated panel actions manage it.

**Tech Stack:** PHP8 sockets, NFQWS2 1.0.6 Lua, shell lifecycle/firewall adapters, React/MUI, Python/PHP/Lua/browser tests.

**Spec:** docs/superpowers/specs/2026-11-01-ip-health-design.md

## Global Constraints

- First incident86400s, repeat604800s, history30days, retest900s, three responsive checks lift; max512 entries.
- No ban from a single timeout, QUIC-only failure, EOF/reset or failed network control; probes bypass desync usingSO_MARK.
- Preserve original core arguments, client exclusions, IPv6-off, other firewall ownership and stopped-service intent.
- Root manifests expire within15s and only validated numeric public endpoints are probed; no per-packet flash writes.
- Existing auth/same-origin/CSRF/updater leases bind all panel actions; DoH/DoT/TCP DNS limitations remain explicit.
- Build80 public binaries/version unchanged during development.

## Review Focus

1. Corrupted/symlinked observations or state must fail open without probing private endpoints or overwriting arbitrary files.
2. Repeated packets in one incident must not promote24h to7days; a new network invalidates old evidence.
3. Missing module/queue collision/controller crash must not stop the original service or leave indefinite refusal.
4. DNS compression, DNSSEC and all-addresses-banned responses must preserve valid original answers.
5. Stale UI mutations and API errors must not imply successful clear/recheck or silently resend.
