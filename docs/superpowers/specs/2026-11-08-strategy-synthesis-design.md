# Standalone strategy synthesis

The user requests a generator, independent of choosing ready profiles. A catalog may inform later search but must not be required. The acceptance experiment disables catalog access entirely and starts with pass-through rules. Existing owner strategies are controls, never hidden templates. Earlier permission to implement/test both owner routers remains; start with the spare. Preserve original settings/resources and follow the latest private owner instructions for final service states. Isolate measurements from upstream bypass services.

Use a bounded grammar of methods actually implemented by the pinned zapret2 1.0.7 standard Lua. No generated executable Lua, downloaded code, shell expressions, arbitrary user operands, DNS or network topology changes. The grammar follows the upstream 1.0.7 manual and blockcheck2 method families. Compile separate HTTP, TLS and QUIC components, including fake+segmentation sequences, valid fooling, split positions and repeat counts. Standard engine blobs avoid external fake dependencies.

Approach: an independent method/parameter matrix, then measurement-directed refinement and synthesis. Pure full Cartesian enumeration is impractical on routers; merely mutating a ready strategy does not satisfy independence. Begin with low-cost representative method families, refine the most promising components, combine protocol winners, and optionally produce host-scoped overrides when distinct methods solve distinct tested domains. Never claim untested combinations work. Record matrix coverage and budget exhaustion explicitly.

Reuse the tested picker journal, update/import exclusion, process identity guard and exact config restoration. A new authenticated `pickersynthesize` action uses no catalog code. It captures a control, builds a fresh AUTO profile using verified standard Lua, fresh private lists and deterministic Detector targets, measures pass-through and generated trials, then measures the assembled finalist twice. Discovery observations are explicitly single exploratory samples and cannot be applied. Telegram is excluded; fixed 80/443 TCP and 443 UDP only. No automatic Apply.

Two independent conclusions: improvement over repeated pass-through and improvement over the owner's repeated original profile. A valid generated profile may be useful from zero while still worse than an already tuned original. Present both, preserve original after the job, and allow a complete dependency-bound export of a validated generated profile. Apply recommendation requires the existing original TLS/YouTube and selected-goal protections. Reports retain raw ratios, not misleading summed percentages. Domain checks do not prove video, voice or feed functionality.

Budgets derive from RAM/CPU/load. All dimensions have finite enums; cap trial count, repeats, output, total monotonic time and per-probe time. Cancellation, crash and foreign edits keep existing restoration semantics. Repeated validation rejects changed targets/context or incomplete runs. Source and package publication are separate from experimental device deployment.

Optional result-window tracker extension is off by default. Reuse the four existing website names, extend only the generated general TLS method, keep excludes and specific/HTTP/QUIC rules intact, add no ports or external dependencies. Allow only verified generated export and existing eligible winner Apply. These sites are not measured by the base run; retain a persistent warning after Apply and inside the exported strategy.
