# Краткий гайд

Пять шагов для первого запуска NFQWS2 ASUS Community.

1. **Проверьте платформу.** ASUS должен работать маршрутизатором. Нужны
   подходящая стабильная Merlin и Entware в `/opt`. Пакет выбирайте по
   `/opt/bin/opkg print-architecture`. Для старых ASUS рекомендуем USB;
   накопитель не добавляет ОЗУ. Проверенный 87U имеет 256 МиБ RAM — это
   объём испытанного устройства, а не минимальное требование.
2. **Установите подходящий IPK.** После установки через opkg откройте
   `http://LAN-адрес-ASUS:90`. По умолчанию используются данные администратора
   ASUS. Чтобы сначала выбрать одно устройство, используйте описанный в
   [README](INSTALL.md) режим установки без
   запуска core. Существующие конфиги при обновлении сохраняются.
3. **Выберите условия проверки.** В «Подготовке ASUS» посмотрите состояние
   ARK. Если он загружен, сначала изучите подготовку с бэкапом. Если отсутствует,
   отключать его не требуется. Выберите одно тестовое устройство, подходящие
   стратегию, списки и DNS. SmartDNS необязателен: важны ответы DNS и адреса
   сервисов, с которыми проверялась стратегия.
4. **Проверьте результат.** Запустите службу, проверьте процесс и привязку
   очереди. Нажмите проверку поступления пакетов и откройте сервис с выбранного
   устройства. Затем проверьте сам сервис. Галочка очереди и рост счётчика
   подтверждают разные этапы; ни один из них сам по себе не гарантирует работу
   сайта, видео или приложения. Сравнивайте новые соединения до и после.
5. **Если нужна помощь или возврат.** Сначала в «Поделиться» соберите
   диагностику и откройте предпросмотр: остановка может изменить важные признаки
   отказа. Отправка добровольная. При необходимости остановите NFQWS2. Настройки ARK
   восстанавливаются из бэкапа в «Подготовке ASUS», с ручной перезагрузкой.
   Если подключали SmartDNS, сначала верните прежний путь DNS, затем остановите
   его. Сохраняйте рабочий резерв связи.

## Если результат отличается

| Что видите | Что проверить первым |
|---|---|
| ARK не загружен, внутренний IDS неизвестен | Это не доказательство неисправности; откройте пояснение «?» и проверьте очередь |
| Процесс есть, счётчик не растёт | Выбран ли реальный IP источника, есть ли новые подходящие соединения; совпадает ли очередь |
| Телефон работает, DPI на роутере — нет | Это разные источники трафика: роутер обычно выходит с адреса WAN, а не своего LAN |
| Стратегия помогает не всем доменам | DNS, выбранный адрес CDN, IPv4/IPv6, протокол и наличие VPN/второго NFQWS2 на пути |
| После остановки SmartDNS пропал доступ по именам | Не осталось ли перенаправление dnsmasq на остановленный SmartDNS |
| После обновления не поменялась стратегия | Активный конфиг сохранён; новые образцы лежат рядом как `*.notactive` |

Точные команды установки, остановки и удаления — в [README](README.md).
Нюансы старых ASUS, ресурсы, SmartDNS, его ограничения и возврат DNS —
в [подробной инструкции](SMARTDNS.md). Установка SmartDNS кнопкой пока
не реализована. [DPI Detector](DPI-DETECTOR.md) — отдельный необязательный
инструмент; на старом 87U официальный бинарник требует совместимой сборки.
