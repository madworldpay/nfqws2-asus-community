# Обновление

## Переход с прежних сборок

**Для перехода с прежних сборок на Build 74 или новее один раз нужен установщик.**
Актуальные выпуски подписываются новым ключом. Для перехода на него повторите
обычную команду установки своей платформы. После этого обновления снова
устанавливаются через панель с проверкой подписи и SHA256.

Это обновление важно для дальнейшего получения исправлений и новых возможностей
через панель. В Build 74 добавлены даты стратегий и временный технический канал
по договоренности с Администратором; исправлены повторная остановка службы
OpenWrt и объяснение отказа проверки SmartDNS. Если вы пропустили обновление
источника каталога, переход также возвращает доступ к актуальным стратегиям
и отправке материалов проекту.

1. Войдите по SSH в роутер и один раз выполните команду своей платформы ниже.
2. После завершения откройте панель и проверьте версию, состояние службы и DNS.
3. Следующие обновления устанавливайте обычными кнопками панели.

Настройки, списки, данные входа и выбранное состояние службы сохраняются.
Уже применённые стратегии продолжают работать и до перехода.

Старые адреса метаданных сохраняют прежний подписанный выпуск; новый ключ не
подменяется через старый канал. Новый установщик получают по HTTPS с GitHub:
ветка ASUS сверяет пакет с `SHA256SUMS` выпуска, ветка OpenWrt дополнительно
проверяет подпись новым встроенным ключом.

Каталог стратегий и приём отправлений находятся на ASUS, материалы доставляются
в Gmail проекта, а выпуски — с GitHub. Для импорта, отправки и обновлений VPS
не требуется.

## Медленная запись USB на ASUS: Build 85/86 → 87

В Build 85/86 создание резервной копии на некоторых USB-накопителях занимало
больше фиксированных 240 секунд. Даже маленький файл может требовать около
секунды на подтверждение записи. Пакет ещё не заменялся, но обработчик завершал
обновление с `timed_out` и восстанавливал прежнюю службу.

В Build 87 и актуальном автономном установщике лимит подготовки рассчитывается
по числу проверенных файлов и двум пробам подтверждённой записи на том же
накопителе. На быстрых накопителях сохраняются 240 секунд, на медленных срок
увеличивается с запасом, максимум до 30 минут. Отдельные сетевые тайм-ауты,
проверки служб и запрет прерывать уже запущенный opkg остаются прежними.
В журнале операции сохраняется `apply-budget.json` с расчётом.

**Если ошибка уже возникает в Build 85/86:** один раз выполните обычную команду
установки ниже. Она использует новый обработчик из актуального скрипта, сохраняя
настройки и прежнее состояние службы. Старый обработчик панели получит исправление
вместе с новым пакетом. Удалять NFQWS2, форматировать USB или перезагружать роутер
для этого перехода не нужно.

## Снимок на старом ASUS и Build 84

В Build 84 исправлен отдельный лимит времени PHP, который мог оборвать создание
снимка на медленном ASUS до начала замены пакета. Если старая панель завершает
обновление на этом шаге, один раз повторите обычную команду установки ниже:
она использует исправленный автономный обработчик. Настройки сохраняются.
Обработчик уже установленной старой сборки не меняется до установки нового пакета.

Актуальная команда установки также учитывает старые конфигурации Entware с
лимитом PHP 8 МБ: только проверенный фоновый установщик получает предел 32 МБ
и освобождает уже распакованные данные перед проверкой пакета. Общий `php.ini`
и лимиты веб-панели не меняются. Для этого исправления установщика пакеты
Build 84 не заменялись; повторная команда получает исправленный скрипт с GitHub.

Также исправлен ложный `timed_out` при запуске обработчика обновления на старых
ASUS: смена исполняемого файла того же процесса больше не принимается за подмену.
Проверки работающего обработчика, срока и менеджера пакетов сохранены. Исправление
доступно в автономном установщике и в панели начиная с Build 85.

## Прерванная установка ASUS

Начиная с Build 81 установщик умеет завершать незавершённую установку именно
NFQWS2 ASUS. Для старой панели повторите обычную команду установки: сначала
проверяются подпись, версия и файлы прерванного пакета, затем выполняется обновление.
Чужая незавершённая установка Entware или работающая операция остаётся причиной
отказа; перезагрузка не заменяет эту проверку.

Обрыв SSH не останавливает уже запущенную установку. При ошибке установщик
показывает путь к сохранённому журналу. Проверьте итоговый статус перед ручным
запуском службы.

## Резервная копия и возврат служб на ASUS в Build 85

Проверка выпуска, скачивание и подготовка пакета оставляют службы работающими.
После нажатия **«Установить обновление»** обновлятор запоминает их состояние
и останавливает NFQWS2 вместе со связанными обработчиками. Затем сохраняет
окончательные настройки, списки и прежний пакет для восстановления, устанавливает
новый пакет и проверяет результат. Службы возвращаются в прежнее состояние:
выключенный NFQWS2 остаётся выключенным. Действующая стратегия сохраняется,
даже если в редакторе находится другой черновик.

При отказе до замены пакета обновлятор проверяет прежнюю установку и возвращает
её службы. Если замена уже началась, проверенный откат возвращает прежний пакет
и настройки. Когда восстановление подтвердить нельзя, резервная копия и журнал
сохраняются, а панель показывает причину. Непроверенная или частично установленная
версия автоматически не запускается.

Начиная с Build 87 штатный обработчик останавливает панель без закрытия живого
технического канала: исключение разрешает только проверенный процесс установки.
Существующее подключение и исходный срок доступа сохраняются. Ручная остановка
панели, отключение канала и истечение срока по-прежнему прекращают доступ.
При первом переходе с Build 85/86 старый код ещё может закрыть канал; понадобится
переподключение с той же действующей ссылкой. Уже оборванный канал автоматически
не воссоздаётся.
Срок технического канала автоматически не продлевается. Потеря питания или всех
обработчиков обновления не даёт оснований запускать службу по устаревшему запросу
после перезагрузки: для такой незавершённой операции нужна новая проверка.

**Первый переход со старой панели:** если она отказывает до установки, один раз
повторите обычную команду установки ниже. Старый установленный обработчик
не получает исправление до замены пакета; команда запускает новый автономный
обновлятор. Настройки и выбранное состояние службы сохраняются.

Прямой `opkg install` не выполняет этот сценарий резервного копирования и отката.
Нативный OpenWrt сохраняет свою проверку пакета и восстановление состояния служб;
полный автоматический возврат прежнего пакета из этого раздела относится к ASUS / Entware.

## Через панель

Панель автоматически проверяет актуальные публичные выпуски GitHub.
Нажмите **«Проверить обновления»**, чтобы узнать, есть ли подходящий выпуск.

В разделе **«Изменения с вашей версии»** показаны описания всех опубликованных
промежуточных билдов, включая целевой, от старых к новым. Описания автоматически
загружаются из публичных выпусков GitHub при открытии окна, без входа в GitHub.
Текст выпусков показан на языке оригинала. Если историю не удалось загрузить
полностью, панель сообщает об этом и оставляет доступным описание целевого
выпуска. Это не мешает подготовке и установке; проверки самого пакета сохраняются.

Эта возможность действует в панели, которая её поддерживает: ранее выпущенные
старые панели не получают новый интерфейс до собственного обновления.

После просмотра изменений:

1. **«Подготовить пакет»** — скачать и проверить подпись, совместимость и свободное место.
2. **«Установить обновление»** — дождаться результата. На ASUS службы останавливаются,
   создаётся резервная копия, заменяется пакет и возвращается прежнее состояние служб.

Панель может временно отключиться. Закрытие вкладки не отменяет установку.
Обновлятор сохраняет настройки, списки, данные входа и выбранное состояние службы «включено / выключено».
Прошивка, ARK и маршруты этим действием не настраиваются; перезагрузка не требуется.

Ранее подтверждённый SmartDNS восстанавливается с сохранённым профилем,
даже если в редакторе находится другой черновик. Черновик сохраняется.
Если пользователь нажал **«Вернуть прежний DNS»**, обновление не подключает
SmartDNS заново. После обновления проверьте версию, состояние службы и DNS:
статус **«SmartDNS подключён»** учитывает и процесс, и реальный путь запросов.
Если восстановление не завершилось, панель показывает причину и подсказку.

## Вручную

**ASUSWRT-Merlin / Entware:**

Скачайте IPK своей архитектуры из [последнего выпуска](https://github.com/madworldpay/nfqws2-asus-community/releases/latest),
проверьте SHA256 по `SHA256SUMS` и передайте файл в `/opt/tmp/nfqws2-asus.ipk`.
Для установки с выключенной обработкой выполните:

```sh
NFQWS_ASUS_NO_START=1 /opt/bin/opkg install /opt/tmp/nfqws2-asus.ipk
```

Для установки с запуском службы используйте ту же команду без `NFQWS_ASUS_NO_START=1`.
Обычный `opkg install` может включить ранее остановленный NFQWS2; панель
и установщик одной командой сохраняют выбранное состояние автоматически.

Повторная установка сохраняет оставленные настройки. Пакет также восстанавливает
отсутствующий обязательный конфиг из текущего шаблона пакета. При существующем
конфиге намеренно удалённые списки не возвращаются.
Если установка прервалась, сохраните вывод и `opkg status nfqws2-asus`:
они помогают отличить ошибку установки от незавершённого восстановления DNS.
В панели откройте **«Экспорт / поделиться»**, соберите диагностику,
проверьте предпросмотр и скачайте JSON или отправьте его проекту.

Для OpenWrt повторите команду нативного установщика ниже; вручную устанавливать
пакет ASUS/Entware на OpenWrt не нужно.

## Если старая панель не находит обновление

Повторно запустите установщик своей платформы в SSH роутера.
Он обновит пакет и сохранит прежнее состояние службы.

### ASUSWRT-Merlin / Entware

```sh
(
  set -e
  umask 077
  nfqws_dir=/tmp/nfqws2-install.$$
  mkdir "$nfqws_dir"
  trap 'rm -rf "$nfqws_dir"' 0
  curl -fL --connect-timeout 10 --max-time 60 \
    https://raw.githubusercontent.com/madworldpay/nfqws2-asus-community/main/install.sh \
    -o "$nfqws_dir/install.sh"
  sh "$nfqws_dir/install.sh"
)
```

### OpenWrt

```sh
(
  umask 077
  nfqws_dir=/tmp/nfqws2-install.$$
  mkdir "$nfqws_dir" || exit 1
  trap 'rm -rf "$nfqws_dir"' 0
  nfqws_url=https://raw.githubusercontent.com/madworldpay/nfqws2-asus-community/main/install.sh
  { curl -fL --connect-timeout 10 --max-time 60 "$nfqws_url" -o "$nfqws_dir/install.sh" || uclient-fetch -T 20 -O "$nfqws_dir/install.sh" "$nfqws_url"; } &&
  sh "$nfqws_dir/install.sh"
)
```

Старые панели могли
использовать только частный канал. После обновления доступна установка
через панель без токена и учётной записи GitHub.

Панель проверяет подпись выпуска закреплённым ключом, затем размер и SHA256 пакета.
При ошибке проверки установка не начинается. Существующий частный канал, если
он задан оператором, продолжает использоваться.

Подробности автоматического возврата прежнего пакета на ASUS — в разделе
**«Резервная копия и возврат служб на ASUS в Build 85»** выше.

После обрыва подготовки можно повторить установку. Собственные настройки канала отправки сохраняются.

### Этапы и причина отказа

Окно показывает текущий этап и процент прохождения этапов, а не время до завершения. При ошибке сохраняются исходный этап и причина, даже если затем восстановлена прежняя версия. «Скопировать ошибку» копирует версии, этап, коды и номер операции. Ошибка текущего соединения с панелью показывается отдельно.

### OpenWrt: остановка, копия и восстановление

Фоновый установщик и его контроллер остановки используют внешний наблюдатель; обычные веб-запросы сохраняют лимит PHP. После старта OPKG/APK процесс менеджера не завершается тайм-аутом. Копия настроек OpenWrt хранится в ОЗУ: расчёт задержки fsync для USB Entware к ней не применяется.

До остановки записывается защищённая идентичность настроек, после остановки — актуальная запись для копирования. При отказе копирования недописанные файлы не считаются повреждённой установленной программой. Прежние службы возвращаются только после проверки старого пакета, версии, сторонних пакетов и настроек. Работающая служба проходит новую остановку/запуск, чтобы восстановить обработку даже после неполной остановки. Исходно выключенная остаётся выключенной.

Частичная замена самого пакета не разрешает запуск непроверенных файлов: журнал сохраняется, а пакет требует восстановления. При сохранённом менеджером состоянии `pending_packages` нужен поддерживаемый путь восстановления пакета; база OPKG/APK вручную не переписывается.
