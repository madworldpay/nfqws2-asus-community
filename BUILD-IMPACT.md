# Как испытания RT-AC87U влияют на сборку

Поставка остаётся прежней: **два объединённых IPK — ARMv7 и AArch64**.
Они имеют общий номер Build. Испытания 87U расширяют поддержку старой
платформы и уточняют диагностику, требования и инструкции.

| Изменение | ARMv7 | AArch64 |
|---|---|---|
| Движок NFQWS2 | Тот же закреплённый движок, распакованный из UPX для старого ядра | Тот же бинарник побайтно |
| Подбор iptables/restore и проверка направления conntrack | Общие проверки, учитывающие старые утилиты | Те же общие проверки; результат определяется на устройстве |
| Частный `ip` службы | Включён | Включён |
| Дополнительный backend NFQUEUE | Только для точного RT-AC87U / 384.13_10 после проверки штатных файлов | Не включён |
| Чтение ARK, пояснения статусов и краткий гайд | Общий WebUI | Общий WebUI |
| SmartDNS и DPI Detector | Отдельные необязательные компоненты | Отдельные необязательные компоненты |

Загрузчик модуля проверяет модель, версию Merlin, архитектуру и контрольные
суммы. Совпадения одного номера ядра недостаточно. Прошивка и образ ядра
не переписываются; на точном профиле подключается дополнительный модуль
в работающую систему. Остановка core не выгружает модуль, который может
использоваться другой программой. Неподходящий модуль принудительно не загружается.

По сравнению Build 20 → Build 26 ARMv7 IPK вырос с 1 943 730 до
2 074 077 байт — примерно на 127 КиБ; AArch64 — с 1 532 053 до
1 537 760 байт, примерно на 6 КиБ. Это размеры скачивания, а не расход RAM.
Последующие изменения только документации могут немного изменить архив.
Сам дополнительный модуль занимает 15 604 байта. Большая часть разницы
ARMv7 также связана с распаковкой движка и комплектом исходников модуля.

Для владельца современного ASUS выбор пакета не меняется: он определяется
основным ABI Entware. Общие проверки запуска тоже обновлены, поэтому новая
сборка требует проверки на современной платформе; прежний движок не делает
остальную службу побайтно прежней. Настройки и списки при обновлении сохраняются.

Новые общие IPv4-проверки отдельно выполнены на действующем GT-BE19000AI:
выбраны Entware iptables и нормальное направление conntrack. Рабочая служба
не останавливалась; её PID, загрузка, конфиги, sysctl и структура всех правил
сохранились. Это проверка preflight, а не установка всей новой сборки на эту
модель. Обнаружена особенность её платформы: даже создание пустой цепочки
через имеющийся iptables сбрасывает общие счётчики политики таблицы mangle.
Это повторилось с Entware и штатной утилитой. Поэтому preflight — активная
проверка netfilter; её нельзя выдавать за чистое чтение счётчиков.
Обычный сбор диагностики и сравнение очереди в WebUI — отдельные операции.

На 87U / 384.13_10 подтверждены очередь и самостоятельный выбранный LAN
IPv4 TCP-трафик с одним DoT. Видео, голос, UDP/IPv6, физические порты/Wi-Fi,
предельная скорость и длительная устойчивость остаются отдельными проверками.
Успех этой модели не означает автоматической поддержки всего старого семейства.

SmartDNS не устанавливается вместе с core и не становится обязательным
требованием. Его смысл и проверенная связка с dnsmasq описаны в
[отдельной инструкции](SMARTDNS.md). Для старого 87U официальный DPI ARMv7
не подошёл по инструкциям процессора/ядра: испытана отдельная soft-float
сборка, ещё не добавленная в обычный установщик. Это ограничение DPI,
а не доказательство неисправности NFQWS2.
